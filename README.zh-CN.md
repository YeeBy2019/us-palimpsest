# us-palimpsest

[English](./README.md) | **简体中文**

> 一张可以走进的美国历史地图。手绘雕版，粒子消散，时间作为第一公民。

**us-palimpsest** 是一个基于 Three.js 的交互式美国历史三维地图集。它把不断变化的疆域、城市的兴衰与决定性的历史事件，绘制在同一张可探索的手绘地图上。时间是第一主轴：时间轴按分节推进，边界如墨水洇开般生长，城市光点逐次亮起；一个时代向另一个时代过渡时，粒子消散开来，又落回纸面。

美术方向参考 [Chartogne-Taillet](https://chartogne-taillet.com/en)——由 Immersive Garden 制作、Bruno Simon 开发，2020 年 12 月 2 日获 Awwwards 每日最佳网站。我们从它身上取几样东西：雕版地图的观感、可见纸面上的水彩晕染、克制的用色，以及唯一一种转场装置——动画粒子——由它把物质从一个场景带到下一个。

## 美术原则

五条，取自参考案例，视为硬性约束。

**1. 一章一种材质。** 每章都渲染成一种可信的实体物质：雕版线条、墨水渲染、水彩洇染、蓝图网格、新闻纸、雷达荧光。章内不混用材质。

**2. 克制的用色，留三处刻意破例。** 参考案例整站建立在单一颜色（`#987654`）之上。我们在全图保持"纸与墨"的基调，各章靠*技法*区分——网线密度、线宽、晕染软硬、洇散半径——而不靠色相。只有三个时刻配得上硬性换色：分裂章的暗红、二战的雷达绿、千禧年的屏幕白。因为稀有，所以有效。

**3. 粒子是唯一的转场。** 只用一种装置，贯彻到底。参考案例从不硬切、从不交叉淡入；上一幕被消散成粒子，而这些粒子成为下一幕的材质。我们照做，并且不再引入第二套转场语汇。

**4. 时间是分节的，不是全局滑动的。** 见下文「时间轴模型」。

**5. 层是沉积下去的，不是叠加上去的。** 见下文「重写本原则」。

## 重写本原则

**结论：层叠要做——但做成纸面之下的沉积，而不是盖在纸上的半透明叠加。**

理由来自参考案例。Chartogne-Taillet 之所以可信，是因为画面里的一切都属于同一种物质：雕版线、水彩、深褐。它的转场并不保留上一幕——笔刷*变成*气泡，气泡*变成*下一幅插图。在新场景之上叠一层半透明的鬼影多边形，会破坏这种统一。在雕版印张上，一道淡淡的错位轮廓读起来像套印误差，而不像历史。

所以这是一条有边界的"要"：

- **只留锚点，不留每一层。** 每章最多保留一到三个*锚点*——历史上具有决定意义的边界状态（1783 年条约线、1803 年购地、1848 年割让、1861 年脱离线）。不是每一代都留，也绝不一次性铺满整部历史。
- **锚点用当章自己的材质来画。** 被保留的边界是去饱和的雕版网线，绝不是一块半透明填色。
- **转场一箭双雕。** 让旧边界消散的那些粒子，正是随后沉积为网线的同一批粒子。消散与沉积是同一个动作，不是两个。
- **锚点在之后两章内可辨，再往后就只是纸。** 拥有它的那一章以全强度绘制；其后两章以递减的网线密度绘制；从第三章起它只是纸纹——不再参与几何绘制，也没有填充率开销。
- **这个窗口本身就是可见上限，不是第二条规则。** 因为窗口是两章，纸面上任何时刻都不会超过三个锚点。「至多可见两到三个」是上一条的算术结果。
- **窗口按章计，不按年计。** 章是导航单位，且各自带有时间尺度。按年计会自相矛盾——1783 年的锚点在第 2、3 两章里会横跨 82 年，而第 6 章里的锚点四年就没了。重写本描述的其实是*页距*：那笔墨是几页之前看到的。

这就是项目名的意思：纸被反复使用，早先的墨迹仍隐约可辨。

### 相对初稿改了什么，为什么

- **纪录片各集的年份区间彼此重叠，还留下了空洞。** 西进（1803–1860s）与分裂（1820s–1860）占用了同一个四十年；腹地（1865–1890s）与城市（1870–1900）占用了同一个二十五年。这在主题式电视叙事里没问题，但一条时间轴上，同一年只能有一个状态。上表按历史转折点重新切分——1783（巴黎条约）、1848（墨西哥割让）、1865、1900、1941、1945、1989——区间不再打架。
- **1783–1803 的空洞已补上。** 原本没有任何一集覆盖这段：邦联时期、《西北法令》（1787）、制宪会议、以及 1803 年的路易斯安那购地。而这些恰恰塑造了此后所有的边界。现在归第 2 章。
- **十二个视觉主题，实际只有七个。** 第 1≡2、4≡5、6≡7、10≡11 集被赋予了完全相同的材质，第 8、9 集同为报纸质感。上表才是诚实的数量。
- **合并策略与主题表自相矛盾。** 它把第 6、7、8 集并为一个连续阶段，可第 8 集的材质（报纸、金色）与第 6、7 集（蓝图、铁锈）并不一致。改为在 1900 年切开即解决。

## 时间轴模型

**章内连续，章间离散。** 这条同时化解了"时间作为第一公民"与分节叙事之间的张力：

- **章是导航单位。** 分节选择器是主要控件——一份章节名列表，如同参考案例底部那份地块名列表，每一章点一下就到。
- **章内时间是连续的。** 日期可以自由拖动；边界按日期从带有效期区间的几何数据实时推导，所以墨水是真正在生长，而不是在若干张存好的画面之间切换。
- **每章自带时间尺度。** 各章不去争夺轴上的固定份额，因此一个四年的章节不会被一个一百六十年的章节压扁。这就是"早期过于拥挤"问题的解法——靠结构解决，而不是靠手调。
- **锚点逐章声明。** 每章一到三个锚点边界状态，加上一组关键事件，数据来自 AHCB 的 `CHANGE` 字段，其中存有每一次边界变更的人类可读说明。

### 数据管线才是真正的活儿

AHCB 发布的全国 shapefile 约 142 MB，内含按日期编码的重叠多边形。这些东西原样进不了浏览器。管线如下：

```
AHCB shapefile
  → 按章节日期范围筛选
  → 用 mapshaper 简化（容差按缩放层级调）
  → 量化并编码为 TopoJSON
  → 每章一份分发包，按需加载
```

每个要素保留 `START_DATE` / `END_DATE`，因此边界在运行时按日期推导，而不是按日期预先烤好。没有成堆的快照需要分发——参考案例同样是这么做的。

### 动效：用 GSAP，以及为什么不手写

本表初稿写的是*不用动效库*，照参考案例的做法。这条推翻了。参考案例手写缓动，是因为它从不需要编排彼此重叠的序列——它的电影模式只是用单一进度值在六种构图之间切换。**而 M4 恰恰改变了这个前提**：从地图飞入历史现场，是编排式的多轨运动——重叠的时间线、错峰的元素、手调曲线——这正是时间线库存在的意义。从 M0 就采用它，意味着相机导演只写一次，且一开始就用 M4 需要的语汇。

三种用途，彼此分开：

- **编排序列**——章节转场、相机导演、粒子消散——用 `gsap.timeline`。
- **连续状态**——章节权重、日期游标、跟随拖拽的相机——用 `gsap.quickTo`，它每次调用都在重新瞄准移动中的目标，而不是重建 tween。
- **瞬移**——深链接与章节跳转——用 `gsap.set`。

### 投影与插图框

地图采用 **Albers 等积圆锥投影**（EPSG:5070，NAD83 / Conus Albers）。它是美国国家级地图的标准——USGS、人口普查局与《美国国家地图集》都用它——而对我们而言理由很具体：它**等积**，州在纸面上的分量与其真实大小一致。墨卡托保的是角度，这正是方形地图瓦片得以成立、也是它成为网页地图标准的原因；但它的面积误差按 1/cos²(纬度) 增长，在 60°N 已达约 4 倍。用墨卡托画，阿拉斯加看上去会比本土四十八州大出好几倍。对一个主题就是"疆域"的项目来说，这是错的工具。

**阿拉斯加与夏威夷做成插图框**，不属于主图。这是符合时代惯例的做法——历史上的美国地图都这么画——也是投影文献推荐的方案，因为强行用一种投影覆盖整个纬度带，会同时扭曲这三块区域。阿拉斯加用 Alaska Albers（EPSG:3338），夏威夷用自己的一套圆锥投影；排布方式即 `d3-geo` 的 `geoAlbersUsa` 所实现的合成布局。哥伦比亚特区 68 平方英里，在州级简化下就是一个标记加一个标签，不是多边形。

**插图框的出现本身就是一次边界事件**，所以它挂在事件成真的那个日期上，而不是挂在加载顺序上：阿拉斯加 1867 年，夏威夷 1898 年。纸面**不会**预先按三块版面定尺寸——日期走到时才生长，相机随之重新取景。在那之前既没有插图框，也没有为它预留的空白，因为当时没有东西可插。

整部地图集的投影是固定的。锚点必须正好压在接替它的那条边界之下；逐章换投影等于刻意破坏这种套准。

### 为什么不用 GitHub Pages

Pages 对站点大小限制 1 GB、单文件限制 100 MB，且不支持 Git LFS。对于一个载荷就是几何数据的项目来说，尺寸不对。用 Vercel——或者继续用 Pages，但把首屏包体限制在单章之内。

### 性能

参考案例选择主动降质而非掉帧：它会在关键时刻采样帧率，指标不够就下调参数，并把选定的画质档位按浏览器记忆下来。我们照做。目标是在核显的中端笔记本上跑满 60 fps，并且每一档画质都必须保持可读。

## 数据来源

- **Newberry Library — Atlas of Historical County Boundaries（AHCB）**，John H. Long 等编，Dr. William M. Scholl 美国历史文化中心。覆盖 **1629-03-04 → 2000-12-31**，精确到日，WGS84；**含全部五十州与哥伦比亚特区，阿拉斯加、夏威夷在内**。全国州与领地合成数据自 1783 年开始；县级数据可回溯至 1629 年。全国数据文件于 2012 年发布，五十州于 2010 年全部完成，项目现已关闭。以下两条的上游都来自它。
- **lmullen/historical-us-boundaries** — 基于同一份数据的交互地图，覆盖 **1783–1912**（据其项目页与地图自身的滑块范围）。有两点值得拿来用：它每个要素的 `CHANGE` 字段存有该次边界变更的人类可读说明，`cw.csv` 存有脱离联邦与重新接纳的日期。这正是第 3、4 章需要的标注层。
- **ropensci/USAboundaries** — 基于同一份 AHCB 数据的 R 包，便于整形与校验推导出的几何。
- **OpenHistoricalMap** — OSM 式的历史地图，同样吸收了 AHCB，值得作为交叉验证来源评估。
- **NHGIS / IPUMS（明尼苏达大学）** — 州与县级边界文件可回溯至 1790 年，1990 年起的全部普查单元齐备，另有可驱动城市光点与聚落密度的入口统计表。免费，但属于**限制性许可**：必须署名，未经许可不得再分发。正因如此，它提供的是统计与交叉验证，而不是我们分发的几何。
- **TIGER/Line（美国人口普查局）** — 现代边界数据的来源，也是我们实际分发的那个。它**不受版权保护**，在产品中使用并致谢普查局即可。NHGIS 从 1990 年起的边界文件本身只是对它的轻度重新包装，因此这是同一份信息，许可更简单。
- **American Panorama**、**Chronicling America** — 交互模式与事件、报纸元数据的参考。

### 覆盖范围的边界，说清楚

- **1629 年之前没有数据。** 第 1 章以 1607 年开场是出于叙事，但边界几何只从 1629 年起存在。1629 年之前只用聚落光点表示，绝不用填色疆域。
- **AHCB 止于 2000 年，但记录没有止。** 第 8 章一直写到当代，因此它从 2000 年起的几何来自 **TIGER/Line**，统计来自 **NHGIS**。这两者发布的是**逐次普查的快照**，而不是带有效期的区间，所以第 8 章是在若干固定状态之间插值，而不是连续生长。这是诚实，而非妥协：2000 年后的变化真实但稀疏，几何本身几乎不动。
- **阿拉斯加、夏威夷与哥伦比亚特区不能简单地砍掉。** Mullen 那张图不含它们，而本文档的早期版本沿用了那个范围却没加以审视。AHCB 本身覆盖全部五十州与特区。排除它们在历史叙述上并不中性：阿拉斯加购地（1867）与夏威夷吞并（1898）都落在第 4 章内；第 6 章以珍珠港开场；1942–43 年的阿留申战役是北美本土唯一的战斗；两者都在 1959 年建州，落在第 7 章内；首府自 1800 年起就在特区，而 1846 年亚历山德里亚县归还弗吉尼亚——那是一次真实的边界变更。**要不要出现**与**怎么画**现在都已定：阿拉斯加、夏威夷用插图框，特区用标记。见上文「投影与插图框」。

## 许可

**代码：MIT。** 见 `LICENSE`。

**数据：CC0 1.0，已无歧义。** AHCB 最初以 CC BY-NC-SA 发布，一些二手资料——包括 rOpenSci 的 `USAboundaries` 文档——至今仍这么写。这个标签此后已被两次取代：Newberry 重建后的站点（2025）明确写明 Atlas 数据以 **Creative Commons CC0 1.0 Universal（公共领域奉献）** 发布，「可无需申请许可即使用」。

本文档早期版本留下的那个问题就此关闭。CC0 是公共领域奉献，因此这份数据可以存在于一个代码为 MIT 的仓库里，两个许可互不沾染——不再需要出于谨慎把它们隔开。

我们仍然把边界数据放在自己的目录、配自己的 `NOTICE` 文件，并在产品内署名来源。不是因为条款要求——条款并不要求——而是因为四十年的州议会法案转录工作不该变得匿名，而这样一份结集值得被引用。

**现代数据源不是 CC0，我们按它们实际的条款对待。** AHCB 的开放是例外，不是通例。**TIGER/Line** 不受版权保护，在产品中致谢普查局即可分发，因此第 8 章的几何以它为准。**NHGIS** 免费，但属于限制性许可：必须署名，未经许可不得再分发，改造后的数据还需重命名并附 FGDC 兼容元数据才可分发。所以 NHGIS 只提供统计与交叉验证，绝不提供分发的几何——何况它 1990 年起的边界文件本就是对 TIGER/Line 的轻度重新包装。两套条款与要求的引用格式都记录在 `NOTICE.md`。

**美术与音频素材：待定。** 原创插画与声音由我们自己授权。第三方采样必须是 CC0 或已明确获准，并登记在 `NOTICE` 中。

**参考材料只引用，不打包。** 纪录片是结构参考；其中任何画面、音频或文稿都不进入本仓库。

## 路线图

已改为深度优先。这个项目的产品就是它看上去的样子——观感不对，别的都救不回来。十条并行的待办只会让所有东西都在动，而真正要紧的那一件事始终没被验证。

### M0 — 垂直切片：先把观感做出来

选一章，标准是边界变化最剧烈、材质最干净：**第 3 章 分裂（1848–1865）**。

- 只为该章搭数据管线
- 程序化纸纹与雕版边缘着色器
- 章内的连续边界形变
- 一次粒子转场进、一次出
- 一个锚点层——1861 年脱离线，在 1865 年州界之下仍可辨认
- 一个两章的选择器，让转场真的能被感受到

*验收标准：*一条十五秒的录屏，能让人开口问"这是怎么做的"。做不到，就先改着色器，不要再写下一个功能。

### M1 — 主脊

八章全部接入。分节选择器、每章的时间尺度、锚点层、转场、相机状态。音频先留桩。

### M2 — 锚点与标注

来自 AHCB `CHANGE` 字段的边界变更标注、城市光点、事件标记。这是内容深度——恰恰是参考案例在评审那里得分最低的地方（内容 7.89，创意 8.53）。把它当成功能来做，而不是点缀。

### M3 — 声音

分章环境音，切章时交叉淡入，首次用户操作后启动。参考案例把声音当作一等层，我们也是。

### M4 — 纵深

从地图飞入历史现场的镜头。注意这里量级变了：这不是数据可视化，而是逐场景的三维美术生产——一个殖民小镇、一片内战战场，各自都是独立的内容工程。单独列一条线，不要让它挡住 M1–M3。

### M5 — 发布

带记忆的画质档位、键盘分节导航、`prefers-reduced-motion`、移动端降级、部署。

### 暂不纳入

- **真实三维地形。** 在观感被验证之前，地图是一张画出来的平面，不是地形模型。
- **上线阶段不做县级几何。** 一万七千多个多边形。先做州与领地级。
- **1629 年之前与 2000 年之后。**

## 开发

尚未初始化脚手架。模块划分、渲染 pass、画质调节器与加载顺序见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)，概览如下：

```
src/
  main.js       启动、帧循环、输入、各系统之间的粘合
  core/         渲染 pass、合成、全局一套 uniform、加载器
  env/          分章状态：权重、色板、日期 → 共享 uniform
  world/        纸面、边界、锚点、标注、相机
  fx/           粒子、城市光点、墨水洇染
  timeline/     八个分章及其叙述
  audio/        分章环境音
  ui/           加载器、章节卡、选择器、控件坞、深链接
pipeline/       AHCB shapefile → 分章 TopoJSON 的构建脚本
public/assets/  直接分发的字体与贴图
data/           生成的各章数据包（不提交）
```

```
npm install
npm run data:build    # 从 AHCB 源数据重新生成各章数据包
npm run dev
npm run build
```
